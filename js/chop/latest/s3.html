S3 and S3-compatible storage

CHOP_ORIGIN=s3://bucket or CHOP_ORIGIN=s3://bucket/prefix reads the originals from a bucket, and --origin s3://bucket works too. The path of a request is appended to the prefix to make the key, so with s3://my-bucket/uploads the request /2026/05/photo.jpg reads the key uploads/2026/05/photo.jpg. Each segment is percent-encoded once, which is what S3 signs, so spaces, +, !, *, ', (, ) and non-ASCII names work. The bucket name follows the S3 rules (3 to 63 lower case letters, digits, dots and hyphens), and a prefix can't have empty, . or .. segments. An s3:// origin can't be combined with an explicit CHOP_DATA_DIR or --data.

chop signs every request to the bucket with AWS Signature Version 4, using only node:crypto. Everything else is the same as for an HTTP origin: the pinned DNS lookup and address checks, no redirects, the size cap while reading, the timeouts, and the fetch limit and queue. CHOP_ORIGIN_ALLOW_HTTP and CHOP_ORIGIN_ALLOW_PRIVATE apply to the endpoint, and URL sources from CHOP_ALLOWED_HOSTS still work next to an S3 origin. They are fetched without a signature, and the credentials are never sent to them.

Setting Environment variable Description
s3Endpoint CHOP_S3_ENDPOINT Base URL of an S3-compatible service, like http://seaweedfs:8333. Unset means AWS. It is checked like an origin: https://, or http:// with CHOP_ORIGIN_ALLOW_HTTP, without user information, a query string or a fragment, and a loopback, private or link-local address needs CHOP_ORIGIN_ALLOW_PRIVATE.
s3Region CHOP_S3_REGION, then AWS_REGION Region that requests are signed for. Required for AWS, and an invalid setting at startup without it. With an endpoint it defaults to us-east-1, and Cloudflare R2 uses auto.
s3PathStyle CHOP_S3_PATH_STYLE true puts the bucket in the path (https://host/bucket/key), false in the host (https://bucket.host/key). Defaults to true with an endpoint and false for AWS.
s3AccessKeyId CHOP_S3_ACCESS_KEY_ID, then AWS_ACCESS_KEY_ID Access key.
s3SecretAccessKey CHOP_S3_SECRET_ACCESS_KEY, then AWS_SECRET_ACCESS_KEY Secret of the access key. Environment only, there is no flag, and it is never logged.
s3SessionToken CHOP_S3_SESSION_TOKEN, then AWS_SESSION_TOKEN Token of temporary credentials, sent and signed as x-amz-security-token. Environment only, and it is never logged.

On AWS the default is the virtual-hosted form, bucket.s3.<region>.amazonaws.com. A bucket name with dots falls back to the path-style form, s3.<region>.amazonaws.com/bucket/key, because the wildcard certificate of AWS doesn't cover dotted names, and CHOP_S3_PATH_STYLE=true forces it. With an endpoint the default is endpoint/bucket/key, and CHOP_S3_PATH_STYLE=false uses bucket.endpoint-host instead, which needs a host name that can have subdomains and not an IP address.

Credentials need both a key and a secret. With only one of them, or with a session token alone, chop doesn't start (an invalid setting, which names the settings and not their values). With neither, requests are sent unsigned, which only works for a bucket with public read access, and chop prints a warning on startup that there are no credentials.

AWS or Lambda, with the credentials of the execution role that Lambda puts in the environment:

CHOP_ORIGIN=s3://my-bucket/uploads AWS_REGION=eu-west-1 chop

SeaweedFS with its S3 gateway on the private network, over plain http:

CHOP_ORIGIN=s3://photos \
CHOP_S3_ENDPOINT=http://seaweedfs:8333 \
CHOP_ORIGIN_ALLOW_HTTP=1 CHOP_ORIGIN_ALLOW_PRIVATE=1 \
CHOP_S3_ACCESS_KEY_ID=chop CHOP_S3_SECRET_ACCESS_KEY=... \
chop

Cloudflare R2:

CHOP_ORIGIN=s3://photos \
CHOP_S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com CHOP_S3_REGION=auto \
CHOP_S3_ACCESS_KEY_ID=... CHOP_S3_SECRET_ACCESS_KEY=... \
chop

A public bucket, without credentials (and with the warning):

CHOP_ORIGIN=s3://public-photos/uploads CHOP_S3_REGION=eu-west-1 chop

SeaweedFS can also serve a bucket through its filer over plain HTTP, which needs no signature and no S3 settings. That is the HTTP origin with the filer URL, CHOP_ORIGIN=http://seaweedfs:8888/buckets/<bucket>, together with CHOP_ORIGIN_ALLOW_HTTP=1 and CHOP_ORIGIN_ALLOW_PRIVATE=1. Use it when the filer isn't exposed to anyone else, and the S3 origin when you want access keys.

Errors are answered like those of an HTTP origin. A missing key (NoSuchKey), a 403 and a 404 are a plain 404 for the client, a 5xx, a network or TLS error and a redirect are a 502, a timeout is a 504 and an object over maxInputBytes is a 413. S3 explains an error in an XML body, and because a signature problem, a wrong key and a missing permission all look like a missing image to the client, chop reads at most the first 2048 bytes of the body of an error (and waits at most two seconds for them) and writes the <Code> to the standard error, like origin ERR_NOT_FOUND: s3.example.com answered 403 SignatureDoesNotMatch. Look there first when images are missing. Other codes to know are AccessDenied, InvalidAccessKeyId, ExpiredToken, RequestTimeTooSkewed, NoSuchBucket and AuthorizationHeaderMalformed (the region is wrong). The codes never reach the client, and neither do the credentials, which are not in any log, warning or error message. A 301 or 307 from S3 means that the bucket is in another region, which chop reports as bucket is in another region (check CHOP_S3_REGION) and doesn't follow.

  • Clock skew. S3 rejects a signature when the clock of the server is more than 15 minutes off, with RequestTimeTooSkewed or a 403. That looks like a permission error, so check the code in the standard error and the time of the container.
  • Credentials from the environment. They are for Lambda and for static keys. chop reads them once at startup and doesn't refresh them, so temporary credentials with a session token stop working when they expire in a long-running process. Restart chop when they rotate, or use static keys for a server. It doesn't read instance metadata, shared credential files or web identity.
  • Interface VPC endpoints. A private endpoint for S3 resolves to private addresses, which chop blocks unless CHOP_ORIGIN_ALLOW_PRIVATE=1 is set. With a custom endpoint that is a host name, set it together with the endpoint.
  • GET only. chop reads whole objects with a signed GET. It doesn't list buckets, use ranges or presigned URLs.
