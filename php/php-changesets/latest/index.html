PHP Changesets

Prepare multi-package releases for PHP projects and monorepos with changeset Markdown files, PHP and Git.

wpelevator/php-changesets releases WordPress plugins, themes and Composer packages from changeset Markdown files, with PHP and Git and without Node.js. It's for projects that don't use Node.js or JavaScript tooling: a Composer dependency replaces an npm one, and nothing needs installing in CI beyond PHP. It follows the release model of wp-release, the Node.js release tool of WP Elevator, so both tools read the same changesets, take the same command options and produce the same release plans.

If your project already builds with Node.js, or you also want ZIPs, checksums, translations or WordPress.org deploys, use the wp-release changeset commands instead. The comparison lists the differences.

Contributors describe each change in a small Markdown file. When you release, the changeset command bumps the versions of every changed package, writes the changelogs and creates the release tags. It never commits or publishes: those steps belong to your workflow, like the GitHub Actions workflow.

Requirements

  • PHP 7.4 or later.
  • Git for tag-based versions, changed-package checks, release tags and dry-run diffs.
  • Composer to install the CLI. Node.js is not required.
